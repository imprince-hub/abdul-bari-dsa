## Code in this folder

Introduction to Queue is theory, and Implementation of Queue repeats the two-pointer queue on the board, so neither has its own code. `SinglePointerQueue`, `ArrayQueue`, `CircularQueue`, `GenericCircularQueue`, `LinkedQueue` and `ArrayDeque` are complete; `LinkedDeque` is still a skeleton. The other files are skeletons: method names are in place and unfinished methods throw `UnsupportedOperationException("TODO")`. All classes use the same messages: a capacity of 0 or less throws `IllegalArgumentException("Capacity must be positive: x")`, a full queue throws `IllegalStateException("Queue is full")` and an empty queue throws `NoSuchElementException("Queue is empty")`. The deques say `Deque` instead of `Queue`, and `ArrayDeque` says `No space at front` or `No space at rear` instead of full, because one end can be blocked while the other end still has space. `LinkedQueue` and `LinkedDeque` have no capacity, so they never throw the capacity or full errors.

| File | What it has |
|------|-------------|
| `SinglePointerQueue.java` | Lecture 2. `int` queue on an array with only `rear` (starts at -1); the first element is always at index 0. `enqueue(value)` puts the value at `++rear` and throws `IllegalStateException("Queue is full")` when `isFull()`. `dequeue()` saves `elements[0]`, moves every element from index 1 to `rear` one step left (`elements[i - 1] = elements[i]`) and then moves `rear` down, so it is O(n) while `enqueue` is O(1); it throws `NoSuchElementException("Queue is empty")` on an empty queue. The shift loop and `display()` stop at `rear`, not at `elements.length`, because the slots after `rear` still hold old values. `isEmpty()` is `rear == -1`, `isFull()` is `rear == elements.length - 1`, `size()` is `rear + 1`. Once the queue is emptied, `rear` is back at -1, so index 0 is used again and no space is lost (unlike `ArrayQueue`, see lecture 6) |
| `ArrayQueue.java` | Lectures 3 to 6. `int` queue on an array with two pointers: `front` is the index just before the first element and `rear` is the index of the last element, both start at -1. `enqueue(value)` puts the value at `++rear` and `dequeue()` returns `elements[++front]`. Both use pre-increment, because the pointer has to move before the array is used; `elements[front++]` would read index -1 first. Both are O(1), because nothing is shifted: a dequeued value stays in the array and only `front` moves past it. `first()` reads `elements[front + 1]` without changing `front` (`++front` there would turn it into a dequeue), `last()` reads `elements[rear]`, and `dequeue`, `first` and `last` throw `NoSuchElementException("Queue is empty")` on an empty queue. `isEmpty()` is `front == rear`, `isFull()` is `rear == elements.length - 1`, `size()` is `rear - front` (no `+ 1`, because `front` is one before the first element). `display()` prints from `front + 1` to `rear`. The pointers are not reset when the queue becomes empty, on purpose, for the lecture 6 drawback |
| `CircularQueue.java` | Lectures 7 and 8. `int` queue on a circular array with the same pointer rule as `ArrayQueue`: `front` is the index just before the first element and `rear` is the index of the last element, both start at 0. `next(index)` is `(index + 1) % elements.length` and every pointer move uses it, so after the last index comes 0 and dequeued slots are used again. `enqueue` moves `rear` with `next` and then writes; `dequeue` moves `front` with `next` and then reads. `first()` reads `elements[next(front)]` and `last()` reads `elements[rear]`. One slot always stays empty, so `isEmpty()` is `front == rear` and `isFull()` is `next(rear) == front`; that is why the array has `capacity + 1` slots and `new CircularQueue(3)` holds 3 elements. `size()` is `rear - front`, plus `elements.length` when `rear` has wrapped behind `front`. `display()` starts at `front`, moves with `next` and stops after printing `rear`. Capacity 0 or less throws `Capacity must be positive: x`, and `Integer.MAX_VALUE` throws `IllegalArgumentException("Capacity is too large: 2147483647")`, because `capacity + 1` would overflow |
| `GenericCircularQueue.java` | Lecture 9. The same circular queue as `CircularQueue` for any `T`, with the same pointer rule, `next(index)`, `isFull()`, `size()` and `display()`. Java does not allow `new T[n]` (type erasure), so the constructor makes an `Object[]` of `capacity + 1` slots and casts it to `T[]` with `@SuppressWarnings("unchecked")`, like m23's `GenericArrayStack`; this is safe because the array never leaves the class. `enqueue(null)` throws `NullPointerException("null elements are not allowed")`, checked before the full check. `dequeue()` moves `front` with `next`, reads the value and then sets that slot to `null`, so the queue does not keep the dequeued object alive and it can be garbage collected. Same exceptions and messages as `CircularQueue` |
| `Node.java` | One node: `data`, `next`, and a constructor |
| `LinkedQueue.java` | Lectures 10 and 11. `int` queue on a singly linked list: `front` is the first node (dequeue side) and `rear` the last node (enqueue side), plus a `size` counter, so `size()` is O(1). No capacity limit, because that is the point of a linked list: every enqueue just makes a new node, so there is no `isFull()` and the constructor takes no argument (in Java `new` never returns `null`; if memory runs out it throws `OutOfMemoryError`). `enqueue(value)` on an empty queue points both `front` and `rear` at the new node, otherwise it links the new node after `rear` and moves `rear` to it. `dequeue()` reads `front.data` and moves `front` to the next node; if that makes `front` `null`, it also sets `rear` to `null`, so both are `null` when the queue is empty and `rear` does not keep the old node alive. `first()` is `front.data`, `last()` is `rear.data`, and `dequeue`, `first` and `last` throw `NoSuchElementException("Queue is empty")` on an empty queue. `isEmpty()` is `front == null`. `display()` walks from `front` to the end. Both `enqueue` and `dequeue` are O(1) |
| `ArrayDeque.java` | Lectures 12 and 14. `int` deque on an array with two pointers, as in the lecture, and not circular: `front` (the index just before the first element) and `rear` (the index of the last element) both start at -1, like `ArrayQueue`. `insertRear` and `deleteFront` are `enqueue` and `dequeue`: `elements[++rear] = value` and `return elements[++front]`. `insertFront` is the reverse of `deleteFront`: it writes into the dead slot that `front` points at and then moves `front` back, so it only works after a `deleteFront` has freed that slot, and it throws `IllegalStateException("No space at front")` when `front` is -1. `deleteRear` is the reverse of `insertRear`: `return elements[rear--]`. `insertRear` checks only `rear == elements.length - 1` and throws `IllegalStateException("No space at rear")`, because the rear can be blocked while the front still has free slots (so `isFull()` is not the right check there). `first()` reads `elements[front + 1]` and `last()` reads `elements[rear]`; `deleteFront`, `deleteRear`, `first` and `last` throw `NoSuchElementException("Deque is empty")`. `isEmpty()` is `front == rear`, `size()` is `rear - front` (every insert adds 1 and every delete takes 1 away, from either end), and `isFull()` is `size() == elements.length`. `display()` prints from `front + 1` to `rear`. Not the same as `java.util.ArrayDeque`, which is circular and grows |
| `DoublyNode.java` | One node for the deque: `data`, `next`, `prev`, and a constructor |
| `LinkedDeque.java` | Lectures 13 and 15. `int` deque on a doubly linked list: `front` and `rear` are both `null` when empty. No capacity limit, like `LinkedQueue`, so no `isFull()`. `insertFront`, `insertRear`, `deleteFront`, `deleteRear`, `first`, `last`, `isEmpty`, `size`, `display`; all stubs |
| `QueueDemo.java` | `main()` that calls one section method per class, plus `demoArrayQueueDrawback()` for lecture 6. `demoSinglePointerQueue()` enqueues 10, 20, 30 into a capacity-4 queue, dequeues once to show the shift, fills the queue and shows the error for an enqueue on a full queue, dequeues everything and shows the error for a dequeue on an empty queue, then enqueues 70 to show the queue works again after emptying. Last, it shows a capacity-1 queue and the error for `new SinglePointerQueue(0)`. `demoArrayQueue()` enqueues 10, 20, 30 into a capacity-4 queue and shows `size`, `first` and `last`, fills it and shows the error for an enqueue on a full queue, dequeues once and shows that `first` is now 20 and that a second `first()` removes nothing, dequeues everything and shows the errors for `dequeue`, `first` and `last` on an empty queue, then shows a capacity-1 queue and the error for `new ArrayQueue(0)`. `demoArrayQueueDrawback()` (lecture 6) fills a capacity-3 queue and dequeues everything, then shows that `isEmpty` and `isFull` are both true and that one more enqueue throws `Queue is full`. Then it fills a capacity-4 queue and dequeues twice: `size` is 2 but `isFull` is true, so the 2 dequeued slots are lost. `demoCircularQueue()` fills a capacity-3 queue and shows the error for a fourth enqueue, dequeues twice and enqueues 40 and 50 so that `rear` wraps to the start of the array (display `30 40 50`), dequeues everything and shows that one more enqueue now works (the `ArrayQueue` drawback is gone), shows the errors for `dequeue`, `first` and `last` on an empty queue, then a capacity-1 queue and the errors for capacity 0 and `Integer.MAX_VALUE`. `demoGenericCircularQueue()` runs the same steps on a `String` queue of colors (red, green, blue, then yellow and white after `rear` wraps), plus the error for `enqueue(null)`, then shows an `Integer` queue with a negative value and the errors for capacity 0 and `Integer.MAX_VALUE`. `demoLinkedQueue()` enqueues 10, 20, 30, dequeues once, then enqueues 40 to 100 to show there is no capacity limit, dequeues everything, shows the errors for `dequeue`, `first` and `last` on an empty queue, and enqueues -5 to show the queue works again after it was emptied. `demoArrayDeque()` shows the `No space at front` error on a new deque, inserts 10, 20, 30 at the rear, deletes two from the front and inserts 20 and 10 back at the front into the freed slots, fills the deque with 40 and 50, shows the `No space at rear` error on a full deque and again after one `deleteFront` (free slot only at the front), deletes from the rear until empty, shows the errors for all four reads and deletes on an empty deque, then a capacity-1 deque and the error for `new ArrayDeque(0)`. `demoLinkedDeque()` only prints its heading so far |
