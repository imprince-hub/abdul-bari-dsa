| `BinaryTree.java` | From m28: the level-order `Integer[]` constructor (`null` means no child), `isEmpty()`, `size()`, `display()` and the helpers `makeChild`, `checkNoValuesLeft`, `childText`. Since lecture 8 every queue here is a `java.util.ArrayDeque<Node>` (used as `Queue<Node>`) instead of m26's `GenericCircularQueue`, because that queue has a fixed capacity and the keyboard constructor cannot know the number of nodes before they are typed. New, lectures 1 and 2: `countRecursive()` counts the nodes by visiting the tree, without reading the `size` field. The public wrapper only calls the private helper with `root`. The helper returns 0 for `null` (this base case also covers the empty tree, so the wrapper needs no `isEmpty()` check) and otherwise `1 + count(lchild) + count(rchild)`, added in the returning phase. One stack frame per level, so a very deep skewed tree hits `StackOverflowError` (around 50,000 levels in a test with the default stack size). New, lectures 3 to 7: `preorderRecursive()`, `inorderRecursive()` and `postorderRecursive()` return the data in visit order as a new `List<Integer>`. They return the list instead of printing, so the iterative versions in later lectures can be checked with `equals`. Each public wrapper makes an `ArrayList`, calls the private helper with `root` and returns the list. The helper does nothing for `null`; otherwise it adds `node.data` before (pre), between (in) or after (post) the two recursive calls. An empty tree gives `[]` without an `isEmpty()` check, the same as `countRecursive`. New, lectures 8 and 9: `BinaryTree(Scanner input, PrintStream prompts)` builds the tree level by level from typed values, like the lecture's create. `input` is where the values come from (`System.in`, or a String in the demo) and `prompts` is where the questions are printed (`System.out`, or a stream that prints nothing), so the same constructor works for the keyboard and for fixed test inputs. `-` means no child, so `-1` stays a normal value. Every node that is made gets two questions (lchild and rchild), and the tree is complete when the queue is empty; values after that are not read. Root `-` gives an empty tree. Every value goes through `makeChild`, the same as the array constructor. `readValue(input, prompts, prompt)` prints the question, reads one token and returns `null` for `-`, otherwise `Integer.parseInt(token)`; it throws `NoSuchElementException("Input ended before the tree was complete")` if no token is left, and a bad token gives `NumberFormatException`. New, lectures 10 and 11: `preorderIterative()` and `inorderIterative()` return the same lists as the recursive versions, but keep their own stack instead of using the call stack, so there is no wrapper and helper pair. The stack is `ArrayDeque<Node>` used as `Deque<Node>` (`push`, `pop`, `isEmpty`), not `java.util.Stack`, which is an old class built on `Vector`. `current` starts at `root` and the loop runs while `current != null || !stack.isEmpty()`. If `current` is not null, push it and go to its lchild (preorder adds `current.data` just before the push). Otherwise pop, and go to the popped node's rchild (inorder adds the popped node's data just before that). Only non-null nodes are pushed, because `ArrayDeque` does not accept null. The loop condition already covers the empty tree, so there is no `isEmpty()` check. The stack is on the heap, so a 1,000,000-level skewed tree works, where `preorderRecursive` throws `StackOverflowError`. Imports are written one per class, not `java.util.*`. New, lectures 12 and 13: `postorderIterative()` uses the lecture's idea that every node goes on the stack two times. The C version marks the second push with a negative address. Java cannot make a reference negative, so the stack is a `Deque<StackEntry>` and every entry carries a `secondTime` flag. If `current` is not null, push `(current, false)` and go to its lchild. Otherwise pop an entry: if `secondTime` is false, push `(entry.node, true)` and go to the node's rchild; if it is true, both subtrees are done, so add the node's data. `current` is already null in that branch, so it is not set to null again (the lecture's `t = NULL`). A node stays on the stack while its rchild's subtree is visited, so a right-skewed tree has every node on the stack at the same time. Tested with 1,000,000-level left-skewed and right-skewed trees. New, lectures 14 and 15: `heightRecursive()` returns the height the way the lecture's code counts it, as the number of levels (nodes on the longest path from the root down to a leaf): empty tree 0, one node 1, `{1..7}` 3. m28's Properties lecture counts height in edges (one node = 0), so levels = that height + 1. Same shape as `countRecursive`: the public wrapper only calls the private helper with `root`. The helper returns 0 for `null` (this base case also covers the empty tree, so there is no `isEmpty()` check) and otherwise `1 + Math.max(height of lchild's subtree, height of rchild's subtree)`, worked out in the returning phase. One stack frame per level, so a 1,000,000-level skewed tree throws `StackOverflowError`. New, lecture 16: `deleteTreeRecursive()` deletes every node in postorder, the lecture's way. Deleting a node in Java means unlinking it (`lchild = null`, `rchild = null`). There is no `free()`; the garbage collector frees a node once nothing points to it. The helper does nothing for `null`, deletes lchild's subtree, then rchild's subtree, and unlinks the node last, in the returning phase, because a node's links are the only way to reach its children. The wrapper calls the helper with `root`, then sets `root = null` and `size = 0`. Without those two lines the root node stayed reachable and `size` kept its old value (`{1..7}` showed size 7 but preorder `[1]`). Deleting an empty tree does nothing and throws nothing. New, lectures 17 and 18: `levelOrderIterative()` returns the data level by level from the root down, left to right inside a level, as a new list. It uses `ArrayDeque<Node>` as `Queue<Node>` (`add`, `remove`, `isEmpty`), the same loop as `display()`: add `root`, then remove a node, add its data, and add its non-null lchild and rchild. Here the `isEmpty()` check is needed (unlike count and height), because `queue.add(root)` with a null root throws `NullPointerException`. No recursion, so 1,000,000-level skewed trees work. The array constructor builds the tree in level order, so for a tree made from an array the result equals the array's values without the nulls |
